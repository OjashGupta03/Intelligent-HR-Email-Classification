# Dataset Guide

## Overview

The Executive AI Chief of Staff uses a curated synthetic dataset of **3,000 executive-level emails** designed to realistically simulate the communication patterns of C-suite executives (CEOs, CTOs, CFOs, Founders, Directors).

---

## Synthetic Dataset Generation

### Generator: `src/data/dataset_loader.py`

The `SyntheticEmailGenerator` creates emails across **corporate scenarios** that executives typically encounter:

| Scenario Category | Example Subjects | Priority Distribution |
|-------------------|------------------|----------------------|
| Financial/Revenue | Q4 revenue shortfall, Budget overrun | Critical / High |
| Legal/Compliance | SEC investigation, Contract breach | Critical / High |
| Customer Issues | Churn risk, Escalation, Complaints | High / Medium |
| Project/Product | Launch delay, Milestone missed | High / Medium |
| Strategic Planning | Board preparation, Acquisition, IPO | High / Medium |
| HR/Organizational | Executive departure, Restructuring | Medium / High |
| Operations | System outage, Supply chain, Security | High / Critical |
| Routine Business | Policy review, Team update, FYI | Medium / Low |
| Networking/Social | Lunch invite, Conference, Thank you | Low |

### Email Structure

Each generated email includes:
- **message_id**: Unique identifier (`<uuid@domain>`)
- **subject**: Realistic executive subject line
- **sender**: Named sender with role (e.g., `Sarah Chen, CFO <cfo@acmecorp.com>`)
- **recipients**: 1–5 recipients with role-appropriate addresses
- **date**: Timestamps spanning a 90-day window
- **body**: 3–15 sentence email body with domain-specific vocabulary
- **in_reply_to / references_field**: Threading headers for reply chains
- **is_reply**: Boolean flag for reply detection

### Reply Thread Generation

~30% of emails are generated as reply threads:
- Original email → 1–4 reply emails
- Replies share thread_id and reference parent message_id
- Subject lines prefixed with "Re: "
- Bodies reference context from the original email

### Dataset Size: 3,000 Emails

| Split | Count | Percentage | Purpose |
|-------|------:|:----------:|---------|
| Train | 1,800 | 60% | Model training |
| Validation | 600 | 20% | Hyperparameter tuning |
| Test | 600 | 20% | Final evaluation |

### Leakage-Safe Splitting

The dataset is split **by sender** (not randomly) to prevent data leakage:
- All emails from a given sender appear in only one split
- This tests the model's ability to generalize to unseen senders
- Prevents the model from memorizing sender-specific patterns

## Annotation Pipeline

### Generator: `src/data/annotation_pipeline.py`

The heuristic annotation pipeline labels each email across multiple dimensions:

### Priority Labels

| Label | Criteria |
|-------|----------|
| `critical` | Emergency keywords, SEC/legal references, outage, P0/Sev1 |
| `high` | Revenue impact, customer escalation, board matters, deadlines |
| `medium` | Compliance, routine risks, policy review, general business |
| `low` | FYI, social, networking, thank-you, routine updates |

### Urgency Labels

Scored 0–100 based on time-pressure signals:
- **critical** (80–100): "immediately", "ASAP", "emergency", "outage"
- **high** (60–79): "urgent", "deadline today", "action required"
- **medium** (40–59): "this week", "follow up", moderate keywords
- **low** (0–39): No urgency signals

### Importance Labels

Scored 0–100 based on business significance:
- **critical** (80–100): Board-level, $M+ financial, legal, CEO involvement
- **high** (60–79): Revenue impact, customer, strategic initiative
- **medium** (40–59): Compliance, general business operations
- **low** (0–39): Social, networking, FYI

### Additional Annotations

| Field | Description |
|-------|-------------|
| `action_required` | Boolean — does the email request action from the executive? |
| `has_commitment` | Boolean — does the email contain a promise or obligation? |
| `has_deadline` | Boolean — does the email reference a specific deadline? |
| `has_risk` | Boolean — does the email mention a business risk? |
| `risk_category` | One of 9 categories (or null) |

### Label Source Tracking

Each annotation is tagged with its source:
- `heuristic` — Generated by the rule-based annotation pipeline
- `gold` — Reserved for future manual human annotations
- `weak` — Lower-confidence programmatic labels

## Using Real Email Data (Enron Corpus)

The system is designed to also work with real email datasets like the Enron Email Corpus:

### Steps to Ingest Enron Data

1. Download the Enron email dataset from [CMU](https://www.cs.cmu.edu/~enron/)
2. Extract to `data/raw/enron/`
3. Use `src/data/email_parser.py` to parse `.eml` files:

```python
from src.data.email_parser import parse_raw_email

with open("email.eml", "r") as f:
    email_dict = parse_raw_email(f.read())
```

4. Run the annotation pipeline on parsed emails:

```python
from src.data.annotation_pipeline import AnnotationPipeline

pipeline = AnnotationPipeline()
annotations = pipeline.annotate_email(email_dict)
```

5. Store in the database via `DatabaseManager.bulk_add_emails()`

### Important Notes for Real Data

- PII should be handled according to your organization's policies
- The email parser strips HTML tags and normalizes headers
- Quoted reply text is automatically removed for clean body extraction
- Thread reconstruction works with standard email headers (In-Reply-To, References)

## Data Storage

### SQLite Database: `data/executive_ai.db`

All processed data is persisted in a local SQLite database:

| Table | Row Count | Description |
|-------|----------:|-------------|
| `emails` | 3,000 | All parsed email records |
| `email_priorities` | 906 | Priority scoring results |
| `threads` | 329 | Reconstructed conversation threads |
| `commitments` | 124 | Detected commitments and promises |
| `risks` | 1,542 | Identified business risks |
| `contacts` | 190 | Unique executive contacts |
| `daily_briefings` | 1 | Generated daily briefings |
| `annotations` | ~3,000 | Heuristic training labels |

### Model Artifacts: `data/models/`

| File | Size | Description |
|------|------|-------------|
| `priority_classifier.pkl` | ~50 MB | Serialized TF-IDF + trained models |
| `email_embeddings.npy` | ~4.4 MB | 3000 × 384 embedding matrix |
| `experiment_results.json` | ~5 KB | Detailed evaluation metrics |
| `training_summary.json` | ~10 KB | Training run summary with feature importance |
